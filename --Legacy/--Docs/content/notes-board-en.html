Notes Board Overview

The Notes Board is an interactive component that displays sticky notes on the dashboard, allowing doctors to create, organize, and manage personal notes. Each note can be customized with different colors, moved around, resized, and linked to alerts. The Notes Board is fully synchronized with the main Notes page, ensuring consistency across both interfaces.

Component Structure

The Notes Board consists of several interactive components that work together to provide a comprehensive note-taking experience.

Header Section

The header includes:

  • Title: "Notes Board" with sticky note icon
  • Add Note Button: Creates a new note with default settings
  • Notes Board Link: Navigates to the main Notes page (/doctor/notes)

Note Widget

Each note is a draggable widget containing:

  • Title Field: Editable text input for note title
  • Content Area: Rich text editor with autocomplete support
  • Action Buttons: Color picker, alert, bring to front, delete
  • Footer: Created and updated timestamps
  • Resize Handle: Corner handle for resizing

Color Picker

Dropdown menu with color options:

  • White: #ffffff
  • Red: #ef4444
  • Black: #1e293b
  • Dodger Blue: #1e90ff
  • Warning Yellow: #fbbf24 (default)
  • Success Green: #10b981

Changing the Theme (Note Color)

Each note can have its own background color, allowing you to organize notes visually by category or priority.

How to Change Color

The color change process:

  • Click Color Icon: Click the palette icon in the note's header
  • Color Picker Opens: A dropdown menu appears with 6 color options
  • Select Color: Click on the desired color square
  • Auto-Update: Note background color changes immediately
  • Auto-Save: Color is saved to database via API call

Technical Implementation

The color change is handled by:

  • Function: dashboardChangeNoteColor(noteId, color)
  • API Call: PUT /api/notes/{id} with background_color parameter
  • Database: Updates notes.background_color column
  • CSS Classes: Dynamically adds/removes color classes (e.g., color-warning)
  • Text Color: Automatically adjusts text color based on background brightness

Synchronization

Color changes are synchronized:

  • Immediate Update: Note color updates instantly in Notes Board
  • Database Save: Color is saved to database immediately
  • Main Page Sync: Color appears correctly when viewing main Notes page
  • Cross-Device: Changes are visible on all devices after refresh

Bring to Front

When multiple notes overlap, you can bring a note to the front to make it the topmost note.

How It Works

The "Bring to Front" feature:

  • Button: Click the layers icon in the note's header
  • Z-Index Calculation: Finds the highest z-index among all notes
  • Increment: Sets the note's z-index to max + 1
  • Visual Update: Note immediately appears on top
  • Auto-Save: New z-index is saved to database

Technical Details

Implementation details:

  • Function: dashboardBringToFront(noteId)
  • Z-Index Query: Scans all notes to find maximum z-index
  • CSS Update: Sets style.zIndex property
  • API Call: PUT /api/notes/{id} with z_index parameter
  • Database: Updates notes.z_index column

Automatic Behavior

Notes are automatically brought to front when:

  • Dragging: Note is brought to front when you start dragging it
  • Resizing: Note is brought to front when you start resizing it
  • Clicking: Note can be brought to front manually via button

Moving the Notes

Notes can be freely moved around the board by dragging them to any position.

Drag and Drop

The drag functionality:

  • Drag Handle: Click and hold on the note's header area
  • Mouse Events: Supports both mouse and touch events
  • Real-Time Movement: Note follows cursor/finger during drag
  • Boundary Constraints: Note stays within container bounds
  • Auto-Save Position: Position is saved when drag ends

Technical Implementation

Drag system components:

  • Start Function: dashboardStartDrag(event, noteId)
  • Drag Function: dashboardOnDrag(event) - updates position
  • Stop Function: dashboardStopDrag() - saves position
  • Position Calculation: Calculates relative position within container
  • API Call: PUT /api/notes/{id} with position_x and position_y

Touch Support

Full touch device support:

  • Touch Events: Supports touchstart, touchmove, touchend
  • Multi-Touch: Handles single touch gestures
  • Prevent Default: Prevents page scrolling during drag
  • Responsive: Works seamlessly on mobile devices

Creating Alerts

The alert creation process:

  • Click Bell Icon: Click the bell icon in the note's header
  • Alert Picker Opens: A dropdown modal appears with date and time fields
  • Set Date: Select the alert date using the date picker
  • Set Time: Enter hour, minute, and AM/PM
  • Create Alert: Click "Create Alert" button
  • Auto-Link: Alert is automatically linked to note content

Alert-Note Linking

The system links alerts to notes:

  • Message Matching: Alert message matches note's HTML content
  • Automatic Detection: System detects if note already has an alert
  • Update Existing: If alert exists, it updates instead of creating new
  • Content Sync: If note content changes, alert message updates
  • Delete on Note Delete: Alert is deleted when note is deleted

Technical Implementation

Alert creation process:

  • Function: dashboardCreateAlertFromNote(noteId)
  • API Endpoint: POST /api/alerts
  • Message Content: Uses note's HTML content as alert message
  • Time Conversion: Converts 12-hour format to 24-hour format
  • Alert Model: Uses AlertModel to create/update alerts
  • Status Display: Note footer shows alert status if alert exists

Deleting Notes

Notes can be deleted individually with a confirmation dialog to prevent accidental deletion.

Deletion Process

The deletion workflow:

  • Click Delete Icon: Click the trash icon in the note's header
  • Confirmation Modal: A confirmation dialog appears
  • Confirm or Cancel: Choose to delete or cancel
  • Animation: Note fades out with scale animation
  • Remove from DOM: Note is removed from the board
  • Database Delete: Note is deleted from database

Associated Data Cleanup

When a note is deleted:

  • Note Record: Deleted from notes table
  • Linked Alert: Associated alert is automatically deleted
  • Alert Matching: System finds alert by matching note content
  • Cascade Delete: All related data is cleaned up

Technical Implementation

Deletion system:

  • Function: dashboardDeleteNote(noteId)
  • Confirmation: dashboardShowDeleteConfirmModal(noteId)
  • API Call: DELETE /api/notes/{id}
  • Controller: NotesController::deleteNote($id)
  • Alert Cleanup: AlertModel::delete() for linked alerts

Resizing Notes

Notes can be resized by dragging the resize handle in the bottom-right corner of each note.

Resize Process

How to resize a note:

  • Resize Handle: Click and hold the diagonal lines in bottom-right corner
  • Drag to Resize: Drag diagonally to change width and height
  • Minimum Size: 250px × 200px (desktop), 250px × 180px (mobile)
  • Maximum Size: Constrained by container bounds
  • Auto-Save: New size is saved when resize ends

Technical Implementation

Resize system components:

  • Start Function: dashboardStartResize(event, noteId)
  • Resize Function: dashboardOnResize(event) - updates dimensions
  • Stop Function: dashboardStopResize() - saves dimensions
  • Size Calculation: Calculates new width/height based on mouse/touch movement
  • API Call: PUT /api/notes/{id} with width and height

Touch Support

Full touch device support:

  • Touch Events: Supports touch-based resizing
  • Prevent Default: Prevents page scrolling during resize
  • Responsive Sizing: Different min sizes for mobile vs desktop
  • Smooth Experience: Works seamlessly on touch devices

Merging with Main Notes Page

The Notes Board displays the same notes as the main Notes page, with real-time synchronization between both interfaces.

Shared Data Source

Both interfaces use the same data:

  • Database Table: notes table stores all note data
  • User Filtering: Only notes for the current user are displayed
  • API Endpoint: Both use GET /api/notes to fetch notes
  • Controller: NotesController::getNotes() handles data retrieval
  • Ordering: Notes ordered by z_index DESC, created_at DESC

Real-Time Synchronization

Changes sync automatically:

  • Create Note: New note appears in both interfaces
  • Update Note: Changes reflect immediately in both places
  • Delete Note: Deletion removes note from both interfaces
  • Position Changes: Note positions sync across interfaces
  • Color Changes: Color updates appear in both places

Data Flow

How data flows between interfaces:

  • Notes Board: Calls loadDashboardNotes() on page load
  • Main Notes Page: Calls loadNotes() on page load
  • Both Fetch: Both call GET /api/notes endpoint
  • Same Data: Both receive identical note data
  • Auto-Refresh: Both can refresh to get latest changes

API Endpoints

Shared API endpoints:

  • GET /api/notes: Fetch all notes for current user
  • POST /api/notes: Create new note
  • PUT /api/notes/{id}: Update note (title, content, color, position, size, z_index)
  • DELETE /api/notes/{id}: Delete note
  • Controller: NotesController handles all operations
Bidirectional Sync:

Changes made in the Notes Board are immediately saved to the database and will appear on the main Notes page when it's loaded or refreshed. Similarly, changes made on the main Notes page will appear in the Notes Board after a refresh. Both interfaces use the same API endpoints and database table, ensuring complete data consistency.

How It Works

The Notes Board is powered by JavaScript for interactivity and PHP controllers for data management.

Database Structure

The notes table stores:

  • id: Primary key
  • user_id: Owner of the note
  • title: Note title
  • content: HTML content of the note
  • background_color: Hex color code
  • position_x, position_y: Note position on board
  • width, height: Note dimensions
  • z_index: Stacking order
  • created_at, updated_at: Timestamps

JavaScript Functions

Key functions in dashboard.js:

  • loadDashboardNotes(): Fetches and renders notes
  • dashboardAddNote(): Creates new note
  • dashboardStartDrag(): Initiates drag operation
  • dashboardStartResize(): Initiates resize operation
  • dashboardChangeNoteColor(): Changes note color
  • dashboardBringToFront(): Brings note to front
  • dashboardCreateAlertFromNote(): Creates alert from note
  • dashboardDeleteNote(): Deletes note

Backend Controller

NotesController methods:

  • getNotes(): Returns all notes for user
  • createNote(): Creates new note
  • updateNote($id): Updates note properties
  • deleteNote($id): Deletes note and linked alert
  • deleteAllNotes(): Deletes all user's notes
