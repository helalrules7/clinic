Summary Statistics

Each report type displays relevant summary statistics in card format, providing quick insights at a glance.

Appointments Summary

Four key metrics displayed in stat cards:

Total Appointments

Sum of all appointments in the selected date range

Completed

Number of appointments with status "Completed"

Missed

Number of appointments with status other than "Completed"

Completion Ratio

Percentage: (Completed / Total Appointments) × 100

Revenue Summary

Financial metrics for revenue reports:

  • Total Revenue: Sum of all payment amounts in EGP
  • Total Transactions: Count of all payment transactions
  • Average Transaction: Total Revenue / Total Transactions
  • Total Discounts: Sum of all discount amounts applied

Patients Summary

Patient demographics metrics:

  • Total New Patients: Count of patients created in the date range
  • Male Patients: Count of male patients
  • Female Patients: Count of female patients
  • Male Percentage: (Male / Total New Patients) × 100

Prescriptions Summary

Medical Prescriptions:

  • Total Prescriptions: Count of distinct prescription records
  • Appointments with Prescriptions: Count of appointments that have prescriptions
  • Patients: Count of distinct patients with prescriptions
  • Avg per Appointment: Total Prescriptions / Appointments with Prescriptions

Glasses Prescriptions:

  • Total Prescriptions: Count of distinct glasses prescription records
  • Appointments with Prescriptions: Count of appointments with glasses prescriptions
  • Patients: Count of distinct patients with glasses prescriptions
  • With Lens Type: Count of prescriptions that have a lens type specified

Database Queries

Report Generation Methods: Each report type uses a specific SQL query in DoctorController.php:

Appointments Report
Tables: appointments Groups by DATE(date), counts total, completed (status='Completed'), and missed (status != 'Completed')
Patients Report
Tables: patients, appointments Groups by DATE(created_at), counts new patients, male, and female
Revenue Report
Tables: payments, appointments Groups by DATE(created_at), sums amount (daily_revenue), counts transactions, sums discount_amount
Medical Prescriptions Report
Tables: prescriptions, appointments Groups by DATE(date), counts distinct prescriptions, appointments, patients, and GROUP_CONCAT drug names
Glasses Prescriptions Report
Tables: glasses_prescriptions, appointments Groups by DATE(date), counts distinct prescriptions, appointments, patients, and with_lens_type

Common Query Pattern:

  • All queries filter by date range using BETWEEN ? AND ?
  • Appointments report excludes today: DATE(date) < CURDATE()
  • Results are grouped by date and ordered ascending
  • Uses aggregation functions: COUNT, SUM, COUNT(DISTINCT), GROUP_CONCAT

Chart.js Integration

Library: Chart.js v4.4.0 (loaded from CDN)

Chart Types Used:

  • Line Charts: For trend visualization (appointments, revenue, patients, prescriptions over time)
  • Doughnut Charts: For status/distribution breakdowns (completed/missed, revenue/discounts, gender, medications, lens types)

Theme Integration:

  • Charts automatically detect theme via getCurrentThemeColors()
  • Theme change listener updates all charts when theme toggle is clicked
  • Colors adapt for text, grid lines, tooltips, and backgrounds
  • Uses MutationObserver to detect class changes on documentElement

Chart Data Preparation:

  • Data is passed from PHP via window.REPORTS_CONFIG JavaScript object
  • Dates are formatted using toLocaleDateString() for display
  • Multiple datasets per chart for comparison (e.g., Total vs Completed vs Missed)
  • Colors use predefined palette with alpha transparency for filled areas

Error Handling

Client-Side:

  • Date range validation (start date must be before end date)
  • Empty state message when no data found for selected period
  • Chart initialization error handling
  • PDF export error handling with user alerts
  • Pagination edge case handling (empty data, single page, etc.)

Server-Side:

  • Authentication check (doctor must be logged in)
  • SQL query error handling with try-catch blocks
  • CSV export error handling with redirect to reports page
  • Default date range if parameters missing
  • Default report type if invalid type provided
