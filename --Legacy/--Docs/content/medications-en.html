Prescription Details Modal

Clicking a prescription card opens a detailed modal showing all medication prescriptions for that patient, organized by appointment with expandable accordion sections.

Modal Structure

Modal Header:

  • Title: "{Patient Name} - Medication Prescriptions"
  • Close button (X) in top-right corner

Appointment Accordion:

Each appointment with prescriptions is displayed as an accordion item:

1
Appointment Header
Shows appointment ID, date, time, visit type, and prescription count. Includes expand/collapse icon (chevron)
2
Action Buttons
"View Appointment" (green) and "Print Prescription" (blue) buttons for each appointment
3
Prescription List
When expanded, shows all medications prescribed in that appointment with full details

Medication Details:

Each medication in the expanded appointment shows:

  • Drug Name: Full medication name (e.g., "CIDAMEX 250 MG 20 TABS.")
  • Rx Symbol: Red "℞" symbol indicating prescription
  • Dose: Medication dosage if available
  • Frequency: How often to take the medication
  • Duration: How long to take the medication
  • Route: Method of administration (e.g., "Topical", "Oral")
  • Special Instructions: Additional notes or instructions if provided

Modal Footer:

  • View Patient Button: Opens patient details page in new tab
  • Close Button: Closes the modal

Accordion Behavior:

  • First (newest) appointment is expanded by default
  • Clicking an appointment header toggles expand/collapse
  • Only one appointment can be expanded at a time (Bootstrap accordion)
  • Chevron icon rotates to indicate state (down = collapsed, up = expanded)

Pagination & Load More

The gallery uses infinite scroll pagination with a "Load More" button to load additional prescription cards as needed.

Load More Button

Features:

  • Initial Load: First 12 prescription cards are loaded automatically
  • Load More: Button appears when more prescriptions are available
  • Loading State: Spinner replaces button during loading
  • Auto-hide: Button hides when all prescriptions are loaded

Button Design:

  • Centered between horizontal lines for visual separation
  • Large, prominent button with down arrow icon
  • Primary blue color to match theme
  • Disabled state during loading to prevent multiple clicks

Pagination Details:

  • Per Page: 12 prescription cards per page
  • Page Tracking: Current page is tracked internally
  • Has More: Server indicates if more pages are available
  • Reset on Filter: Pagination resets when patient filter is applied or cleared

Empty State

When no medication prescriptions are found, a friendly empty state message is displayed to inform the user.

Empty State Display

When Shown:

  • No medication prescriptions exist in the system
  • Patient filter returns no results
  • All prescriptions have been loaded and none remain

Empty State Content:

  • Large capsule icon (muted color)
  • Heading: "No medication prescriptions found"
  • Message: "No medication prescriptions are available at this time."

Technical Implementation

Technical details about the Medications Prescriptions implementation, including API endpoints, database queries, JavaScript functions, and workflow algorithms.

API Endpoints

GET /doctor/medications

Main medications prescriptions gallery page

GET /api/medications/prescriptions

Get paginated medication prescriptions grouped by patient

Query Parameters:
  • page - Page number (default: 1)
  • patient_id - Optional filter by patient ID
Response:
  • success - Boolean indicating success
  • data - Array of patient prescription objects
  • pagination - Pagination metadata (current_page, total_pages, total, per_page, has_more)
GET /api/medications/prescriptions/patient

Get all medication prescriptions for a specific patient, grouped by appointment

Query Parameters:
  • patient_id - Required patient ID
Response:
  • success - Boolean indicating success
  • data - Array of appointment objects, each containing prescriptions array
GET /api/patients/search

Search patients by name for autocomplete (used by patient filter)

Query Parameters:
  • q - Search query (minimum 2 characters)
  • limit - Maximum results (default: 10)

Database Queries

Main Gallery Query:

getMedicationsPrescriptions()
Tables: prescriptions, appointments, patients Groups prescriptions by patient_id, counts distinct appointments per patient, gets latest prescription date, and includes latest prescription details for thumbnail

Patient Prescriptions Query:

getPatientMedicationsPrescriptions()
Tables: appointments, prescriptions Gets distinct appointments with prescriptions for a patient, then fetches full prescription details for each appointment, ordered by date DESC

Query Features:

  • Uses GROUP BY to group prescriptions by patient
  • Uses COUNT(DISTINCT appointment_id) to count appointments, not prescriptions
  • Uses MAX(created_at) to get latest prescription date
  • Supports optional WHERE clause for patient filtering
  • Orders results by latest prescription date (DESC)
  • Pagination using LIMIT and OFFSET

Error Handling

Client-Side:

  • Loading indicators during API calls
  • Empty state display when no results found
  • Error handling in fetch promises with console logging
  • Debounced search to prevent excessive API calls
  • Input validation (minimum 2 characters for search)
  • XSS protection via escapeHtml() function

Server-Side:

  • Authentication check (doctor or admin role required)
  • Input validation (patient_id must be integer)
  • SQL query error handling with try-catch blocks
  • JSON error responses with appropriate HTTP status codes
  • Empty result handling (returns empty array, not error)
