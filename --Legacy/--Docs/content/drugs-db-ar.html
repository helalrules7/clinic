التصفية والنتائج

قم بتحسين نتائج بحثك باستخدام فلاتر دقيقة واستعرض القوائم التفصيلية.

الفئة (Category)

تصفية حسب التصنيف العلاجي (مثلاً: مضاد حيوي، مسكن، مضاد للهستامين).

بحث الشركة

تضييق النتائج لعرض الأدوية من شركة مصنعة محددة فقط.

طريقة الاستخدام (Route)

تصفية حسب طريقة التعاطي (فموي، حقن وريدي، موضعي، قطرات عين، إلخ).

وظائف JavaScript

الفئة: DrugSearch (في @app/Views/doctor/assets/js/drugs.js)

الطرق الرئيسية:

constructor()
تهيئة الفئة، إعداد مراجع DOM
init()
إنشاء البوابة، إعداد مستمعي الأحداث
performSearch()
دالة البحث الرئيسية، تستدعي /api/searchDrugs
showDrugDetails()
جلب وعرض نافذة تفاصيل الدواء
loadMoreResults()
زيادة الصفحة وتحميل الدفعة التالية
applyFilters()
تطبيق الفلاتر المحددة وتنفيذ البحث
createPortal()
إنشاء بوابة اقتراحات الإكمال التلقائي
debounce()
دالة مساعدة (تأخير 300ms)

وظائف التحديث:

startDatabaseUpdate()
بدء عملية التحديث
updateProgress()
تحديث شريط التقدم

الملفات الرئيسية

@app/Views/doctor/drugs.php
هيكل HTML الرئيسي لصفحة بحث الأدوية
@app/Views/doctor/assets/js/drugs.js
جميع منطق البحث والتفاعل
@app/Views/doctor/assets/css/drugs.css
التنسيق لصفحة الأدوية
@app/Controllers/DoctorController.php
يعرض صفحة الأدوية (طريقة drugs())
@app/Controllers/ApiController.php
جميع نقاط نهاية API:
  • searchDrugs(), getDrugDetails(), getFilterOptions()
  • searchDrugsAutocomplete(), getMostUsedDrugs()
  • updateDrugsDatabase(), getDrugsDatabaseConnection()
@index.php
يحدد جميع مسارات API (GET /doctor/drugs، GET /api/searchDrugs، إلخ)

نظام التصفية

أنواع التصفية:

  • الفئة (Pharmacology): التصنيف العلاجي
  • الشركة: فلتر الشركة المصنعة
  • الطريقة (Route): طريقة التعاطي

السلوك:

  • يمكن تطبيقها بشكل مستقل أو مجتمعة
  • تعمل مع أو بدون مصطلح بحث
  • تتطلب النقر على زر "تطبيق الفلاتر" (ليس تلقائياً)
  • إشارة بصرية عند تحديد الفلاتر

التحميل: الخيارات محمّلة عبر /api/getFilterOptions عند تهيئة الصفحة

اختصارات لوحة المفاتيح

ملاحظة: بينما تذكر الواجهة اختصارات لوحة المفاتيح (F أو ب للبحث، Esc للمسح)، فإن التنفيذ الفعلي في drugs.js لا يتضمن مستمعي أحداث لوحة المفاتيح.

يتم عرض الاختصارات في الواجهة ولكن يجب تنفيذها بشكل منفصل إذا رغبت.

معالجة الأخطاء

من جانب العميل:

  • مؤشرات التحميل أثناء استدعاءات API
  • رسالة "لا توجد نتائج" عند البحث الفارغ
  • تسجيل رسائل الخطأ في وحدة التحكم (يمكن تحسينها بإشعارات toast)

من جانب الخادم:

  • التحقق من المصادقة أولاً (401 إذا لم يكن مصرحاً)
  • التحقق من المدخلات (الحد الأدنى لطول البحث، المعاملات المطلوبة)
  • التقاط أخطاء اتصال قاعدة البيانات وإرجاعها كأخطاء 500
  • التراجع عن المعاملة عند الفشل
  • تنظيف الملفات المؤقتة حتى في حالة الأخطاء
