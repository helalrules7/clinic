View As Overview

The View As - Role Interface Preview component allows administrators to preview the system interface as it appears to different user roles (Doctor and Secretary). This feature helps admins understand user experience, test functionality, and troubleshoot role-specific issues without switching accounts.

Role Preview

Safe Testing

Easy Return

Includes a quick "Return to Admin" button to exit preview mode and return to the admin dashboard instantly.

How It Works

The View As feature uses session management to temporarily change the user's effective role.

Backend Processing

AdminController::viewAs() method:

  • Authorization: Only allows users with 'admin' role
  • Role Validation: Validates role parameter (must be 'doctor' or 'secretary')
  • Session Management: Calls Auth::startViewAs($role)
  • Redirect: Redirects to appropriate dashboard (/doctor/dashboard or /secretary/dashboard)
  • Query Parameter: Adds ?view_as=1 to indicate preview mode

Session Management

Auth::startViewAs($role) method:

  • Session Variables: Sets $_SESSION['view_as_mode'] = true
  • Role Storage: Stores viewed role in $_SESSION['view_as_role']
  • Original Role: Saves original admin role in $_SESSION['original_role']
  • User Object Update: Temporarily updates user role in session

Stopping View As

AdminController::stopViewAs() method:

  • Session Cleanup: Calls Auth::stopViewAs()
  • Role Restoration: Restores original admin role from session
  • Redirect: Redirects back to /admin/dashboard
  • Success Message: Shows success message in query parameter

Role Detection

Auth::getCurrentRole() method:

  • View As Check: Checks if isViewAsMode() returns true
  • Role Return: Returns viewed role if in View As mode, otherwise returns actual user role
  • Permission Checks: All permission checks use getCurrentRole() for accurate role-based access

Security & Limitations

The View As feature includes security measures and limitations to ensure safe usage.

Access Control

Security measures:

  • Admin Only: Only users with 'admin' role can use View As
  • Role Validation: Only 'doctor' and 'secretary' roles can be previewed
  • Session-Based: View As mode is stored in session, not database
  • Automatic Cleanup: Session variables are cleared when stopping View As

Visual Indicators

When in View As mode:

  • Warning Alert: Yellow alert box at top of dashboard
  • Query Parameter: ?view_as=1 in URL
  • Return Button: Always visible to exit preview mode
  • Original Role Display: Shows original admin role for reference

Limitations

View As mode limitations:

  • Temporary: View As mode is session-based and doesn't persist across sessions
  • Role Restrictions: Only 'doctor' and 'secretary' roles can be previewed
  • No Data Modification: While in View As mode, admin privileges are maintained for data safety
  • Single Role: Can only preview one role at a time
