Login System Overview

The Login system provides secure authentication for users to access the clinic management system. It includes password verification, session management, remember me functionality, login throttling, and theme persistence that syncs between localStorage and the database.

Session Management

Creates secure sessions with inactivity timeout (4 hours) and remember me functionality for extended access.

How Login Works

The login process involves multiple steps from form submission to session creation and theme synchronization.

Step 1: Form Submission

Client-Side: User fills username and password, optionally checks "Remember me"

Validation: JavaScript validates username (min 3 chars) and password (required)

CSRF Protection: Form includes CSRF token from $this->csrfField()

Submission: POST request to /login endpoint

Step 2: Backend Processing (AuthController)

CSRF Validation: validateCsrfToken() verifies token

Input Validation: Validator checks username (required, min:3) and password (required)

Login Attempt: Calls $this->auth->login($username, $password)

File: app/Controllers/AuthController.php::login()

Step 3: Authentication (Auth.php)

Throttling Check: isThrottled() prevents brute force attacks

User Lookup: Queries users table for active user with matching username

Password Verification: password_verify($password, $user['password_hash'])

Failed Login Tracking: Records failed attempts in session if credentials invalid

File: app/Lib/Auth.php::login()

Step 4: Session Creation

Session Variables: createSession($user) sets:

  • $_SESSION['user_id'] - User ID
  • $_SESSION['user'] - Full user object
  • $_SESSION['role'] - User role
  • $_SESSION['last_activity'] - Timestamp for inactivity timeout
  • $_SESSION['login_time'] - Login timestamp

Last Login Update: Updates last_login_at in users table

Step 5: Remember Me (Optional)

Condition: If "Remember me" checkbox is checked

Token Creation: createRememberToken($userId) generates secure random token

Database: Stores token in user_sessions table with expiration

Cookie: Sets remember_token cookie with HttpOnly and Secure flags

Duration: Configured in AuthConfig::REMEMBER_ME_DURATION

Step 6: Role-Based Redirect

Function: redirectByRole($user['role'])

Redirects:

  • Doctor: /doctor/dashboard
  • Secretary: /secretary/dashboard
  • Admin: /admin/dashboard

Session Save: session_write_close() ensures session is saved before redirect

Theme Persistence and Synchronization

The login page theme selection is automatically saved to localStorage and synchronized with the database after successful login, ensuring theme consistency across sessions.

Theme Toggle on Login Page

Button: Fixed position toggle button (top-right)

JavaScript Function: updateThemeUI(theme) in login.php

Action: Toggles dark class on document.documentElement

Icon Update: Changes icon between moon (dark) and sun (light)

Storage: Saves to localStorage.setItem('appTheme', theme) and localStorage.setItem('theme', theme)

Theme Loading on Page Load

Priority Order:

  1. localStorage.getItem('appTheme')
  2. localStorage.getItem('theme')
  3. System preference: window.matchMedia('(prefers-color-scheme: dark)')
  4. Default: 'light'

Application: Theme is applied immediately on page load via updateThemeUI(saved)

Theme Sync After Login

Location: Main layout JavaScript (main.js or secretary_main.php)

Process:

  1. Reads theme from localStorage (priority)
  2. Loads theme from database via /api/doctor/settings GET
  3. If localStorage theme differs from database, saves localStorage theme to database
  4. If no theme in database but exists in localStorage, saves it to database

API Endpoint: PUT /api/doctor/settings with {theme: 'dark'|'light'}

Database Storage

Table: doctor_settings (or role-specific settings table)

Columns:

  • user_id - User ID
  • setting_key - 'theme'
  • setting_value - 'dark' or 'light'
  • setting_type - 'string'
  • updated_at - Timestamp

Query: INSERT ... ON DUPLICATE KEY UPDATE for upsert operation

Controller: DoctorController::apiUpdateSettings()

Theme Application in UI

After Login: When user is redirected to dashboard, theme from localStorage is applied

CSS Variables: Theme changes update CSS custom properties:

  • --bg, --text, --card, --muted, --accent
  • Light theme: Light backgrounds, dark text
  • Dark theme: Dark backgrounds, light text

Persistence: Theme persists across page reloads and browser sessions

Settings Page Integration

Alternative: Users can also change theme from Settings page

Sync: Changes from Settings page also update localStorage and database

Consistency: Theme preference is always synced between localStorage and database

Security Features

The login system includes multiple security measures to protect against common attacks.

Password Hashing

Algorithm: bcrypt via PHP password_hash()

Verification: password_verify($password, $hash)

Configuration: Uses AuthConfig::PASSWORD_ALGO and PASSWORD_OPTIONS

Storage: Hashed passwords stored in users.password_hash column

CSRF Protection

Token Generation: CSRF token generated and stored in session

Form Field: $this->csrfField() adds hidden input with token

Validation: validateCsrfToken() compares POST token with session token

Method: Uses hash_equals() for timing-safe comparison

Login Throttling

Purpose: Prevents brute force attacks

Mechanism: Tracks failed login attempts per IP address in session

Threshold: AuthConfig::MAX_LOGIN_ATTEMPTS (default: 5)

Lockout Duration: AuthConfig::LOCKOUT_DURATION (default: 15 minutes)

Reset: Failed attempts reset on successful login

Session Timeout

Duration: 4 hours of inactivity

Tracking: $_SESSION['last_activity'] updated on each request

Validation: isSessionValid() checks time since last activity

Expiration: Session destroyed if timeout exceeded, user redirected to login

Secure Remember Me

Token Generation: Cryptographically secure random bytes via random_bytes()

Storage: Token stored in user_sessions table with expiration

Cookie Flags: HttpOnly (prevents JavaScript access) and Secure (HTTPS only)

Validation: Token validated against database on each request

Active User Check

Query Filter: Only active users (is_active = 1) can log in

Purpose: Allows administrators to disable user accounts

Location: User lookup query in Auth::login()

Technical Implementation

Key files, functions, and database structures that power the login system.

Key Files

  • View: app/Views/auth/login.php - Login page template
  • Controller: app/Controllers/AuthController.php - Login logic
  • Library: app/Lib/Auth.php - Authentication methods
  • Config: app/Config/Auth.php - Authentication configuration
  • Layout JS: app/Views/layouts/main.js - Theme sync logic

Key Functions

  • Auth::login($username, $password) - Authenticates user
  • Auth::createSession($user) - Creates PHP session
    • Auth::setRememberMe($userId) - Creates remember token
  • Auth::check() - Verifies authentication status
  • AuthController::login() - Handles login POST request
  • updateThemeUI(theme) - Updates theme in login page
  • saveThemeToDatabase(theme) - Saves theme to database
  • loadThemeFromDatabase() - Loads theme from database

Database Tables

  • users: User accounts with password_hash, is_active, last_login_at
  • user_sessions: Remember me tokens with expiration
  • doctor_settings: User preferences including theme (setting_key='theme')
  • doctors: Doctor-specific data joined with users

API Endpoints

  • GET /login - Shows login page
  • POST /login - Processes login form
  • GET /api/doctor/settings - Retrieves user settings (including theme)
  • PUT /api/doctor/settings - Updates user settings (including theme)

Theme Synchronization Flow

Complete flow of how theme selection on login page is persisted and synchronized.

1. User Changes Theme on Login Page

Action: User clicks theme toggle button

JavaScript: themeToggleBtn.onclick handler

Storage: localStorage.setItem('appTheme', next)

UI Update: updateThemeUI(next) applies theme immediately

2. User Logs In

Process: Authentication succeeds, session created

Redirect: User redirected to role-specific dashboard

Theme State: Theme preference remains in localStorage

3. Dashboard Loads Theme

Priority: Reads from localStorage first (fast, synchronous)

Fallback: If no localStorage theme, loads from database

Application: Theme applied to dashboard UI

JavaScript: loadThemeFromDatabase() in main layout

4. Theme Synchronization

Comparison: Compares localStorage theme with database theme

Sync Logic:

  • If localStorage differs from database → Save localStorage to database
  • If no database theme but localStorage exists → Save to database
  • If no localStorage but database exists → Load to localStorage

API Call: PUT /api/doctor/settings with theme value

5. Database Update

Table: doctor_settings

Operation: INSERT ... ON DUPLICATE KEY UPDATE

Columns: user_id, setting_key='theme', setting_value='dark'|'light'

Controller: DoctorController::apiUpdateSettings()

6. Future Sessions

On Login: Theme loaded from database if no localStorage

On Dashboard: Theme always synced between localStorage and database

Consistency: Theme preference persists across devices and sessions
