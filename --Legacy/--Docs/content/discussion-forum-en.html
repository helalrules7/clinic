Discussion Forum Overview

The Discussion Forum provides a comprehensive platform for doctors to discuss cases, share knowledge, ask questions, and collaborate. It includes topic creation, threaded comments, tags, attachments, pinning, resolution tracking, and like/dislike functionality.

Like/Dislike

Users can like or dislike both topics and comments to express agreement or disagreement, with real-time count updates.

Main Forum Page

The main forum page displays category statistics, top meta tags, search functionality, pinned topics, and regular topics with filtering and sorting capabilities.

Category Statistics Cards

At the top of the forum page, statistics cards show the count of topics in each category:

  • All: Total count of all topics
  • General Discussion: Topics in general discussion category
  • Clinical Case: Topics related to clinical cases
  • Procedure Feedback: Topics about procedure feedback
  • Protocol Update: Topics about protocol updates
  • Drug Interaction: Topics about drug interactions
  • Prescription Inquiry: Topics about prescription inquiries
  • Lab/Imaging Interpretation: Topics about lab or imaging interpretation

Functionality: Clicking a category card filters the forum to show only topics in that category. The active category is highlighted.

Implementation: Cards are loaded via /api/forum/category-stats endpoint and rendered dynamically by loadCategoryStats() in forum_index.js.

Top Meta Tags

Below the category statistics, the top meta tags section displays the most frequently used tags across all topics:

  • Patient Tags (@): Tags linking to specific patients
  • Appointment Tags (#): Tags linking to specific appointments
  • Drug Tags ($): Tags linking to specific drugs
  • Custom Tags: User-defined custom tags

Display Format: Each tag shows the tag name and the count of topics using that tag (e.g., "Ahmed zien Zien (3)").

Functionality: Clicking a tag filters the forum to show only topics containing that tag.

Implementation: Tags are loaded via /api/forum/top-meta-tags endpoint and rendered by loadTopMetaTags() in forum_index.js.

Search Functionality

The forum includes a powerful search bar with autocomplete functionality:

  • Search Input: Located at the top of the forum, allows searching by topic title or content
  • Autocomplete: As you type (minimum 2 characters), suggestions appear showing matching topics with title, preview, category, and author
  • Keyboard Navigation: Use arrow keys to navigate suggestions, Enter to select, Escape to close
  • Real-time Filtering: Topics are filtered in real-time as you type (with debounce)

Implementation: Search is handled by searchTopicsAutocomplete() and loadTopics() functions in forum_index.js, calling /api/forum/topics?search=... endpoint.

New Discussion Button

A prominent "New Discussion" button in the toolbar opens a modal for creating new topics:

  • Location: Top right of the forum toolbar
  • Icon: Plus circle icon with "New Discussion" text
  • Action: Opens the "Create New Discussion" modal

Pin Posts Feature

Purpose: Pin important topics to keep them at the top of the forum for maximum visibility.

How to Pin:

  • Open any topic page
  • Click the pin icon button in the top-right corner of the topic
  • The topic will be moved to the "Pinned Topics" section at the top of the forum

Visual Indicator: Pinned topics display a pin icon (📌) next to the title and appear in a separate "Pinned Topics" section with a pin icon header.

Permissions: All doctors can pin/unpin topics (not restricted to admins).

Implementation: Pin status is toggled via togglePin(topicId) function in topic.js, calling PUT /api/forum/topics/{id}/pin endpoint in ForumController.php.

Database: Pin status is stored in the is_pinned column of the doctor_forum_topics table.

Sorting: Pinned topics are sorted by is_pinned DESC, last_reply_at DESC, created_at DESC to ensure pinned items appear first.

  • Actions: Pin, Edit, Delete buttons (if user has permissions)

Tags System

The forum includes a powerful meta tags system that allows linking topics to patients, appointments, drugs, or custom tags for better organization and filtering.

Patient Tags (@)

Usage: Type @ followed by patient name to tag a patient.

Autocomplete: As you type after @, an autocomplete dropdown appears showing matching patients with:

  • Patient name (first name + last name)
  • Phone number

Selection: Use arrow keys to navigate, Enter or click to select. The tag appears as a badge with a person icon.

Functionality: Patient tags are clickable and link to the patient's profile page (/doctor/patients/{id}).

Implementation: Patient autocomplete is handled by initMetaAutocomplete() in forum_index.js, calling /api/patients/search endpoint.

Appointment Tags (#)

Usage: Type # followed by appointment number to tag an appointment.

Autocomplete: As you type after #, an autocomplete dropdown appears showing matching appointments with:

  • Appointment number (#ID)
  • Patient name
  • Date and time

Selection: Use arrow keys to navigate, Enter or click to select. The tag appears as a badge with a calendar icon.

Functionality: Appointment tags are clickable and link to the appointment details page (/doctor/appointments/{id}).

Implementation: Appointment autocomplete is handled by initMetaAutocomplete() in forum_index.js, calling /api/appointments/search endpoint.

Drug Tags ($)

Usage: Type $ followed by drug name to tag a drug.

Autocomplete: As you type after $, an autocomplete dropdown appears showing matching drugs from the hclinic_drugs database with:

  • Drug name (FirstName from drugs table)
  • Drug ID

Selection: Use arrow keys to navigate, Enter or click to select. The tag appears as a badge with a capsule icon.

Functionality: Drug tags are clickable and open a popover showing drug information when clicked.

Implementation: Drug autocomplete is handled by initMetaAutocomplete() in forum_index.js, calling /api/drugs/search endpoint. Drug information is fetched from the hclinic_drugs database.

Custom Tags

Usage: Type any custom text and press ; (semicolon) or Enter to create a custom tag.

Format: Custom tags can contain any text and are displayed with a tag icon.

Functionality: Custom tags are not linked to any entity but can be used for general categorization or keywords.

Implementation: Custom tags are stored in the doctor_forum_tags table with tag_type='custom' and tag_name containing the custom text.

Tag Filtering

Top Meta Tags Section: The most frequently used tags appear at the top of the forum with usage counts.

Click to Filter: Clicking any tag (patient, appointment, drug, or custom) filters the forum to show only topics containing that tag.

Implementation: Tag filtering is handled by filterByMetaTag() in forum_index.js, which sets currentMetaFilter and calls loadTopics() with meta_type and meta_id or meta_name parameters.

Mark Resolved

Topics can be marked as resolved when questions are answered or cases are closed, helping organize discussions and track completion status.

Resolved Status

Purpose: Mark topics as resolved to indicate that questions have been answered or cases have been closed.

Visual Indicator: Resolved topics display a green "Resolved" badge with a checkmark icon (✔ Resolved) next to the category badge.

Restrictions: Topics in the "General Discussion" category cannot be marked as resolved (this restriction is enforced in the backend).

How to Mark Resolved:

  • Open the topic page
  • Click the "Mark Resolved" button (green button with checkmark)
  • The topic will display the "Resolved" badge
  • Click again to unmark as resolved

Permissions: All doctors can mark topics as resolved (not restricted to admins or topic authors).

Implementation: Resolved status is toggled via toggleResolved(topicId) function in topic.js, calling PUT /api/forum/topics/{id}/resolve endpoint in ForumController.php.

Database: Resolved status is stored in the is_resolved column of the doctor_forum_topics table.

The topic page displays the full topic content, attachments, tags, and all replies in a hierarchical threaded structure.

Back to Forum Button

A "Back to Forum" button with a left arrow icon appears at the top-left of the topic page, allowing quick navigation back to the main forum page.

The topic content section displays:

  • Author Info: Author name, avatar, and "By [Name] • [time ago]"
  • Metadata: Views count (👁️), replies count (💬)
  • Patient/Appointment Badges: If the topic is linked to a patient or appointment, badges appear with links

  • Tags: All tags (patient, appointment, drug, custom) displayed as clickable badges

If a topic has attachments, they are displayed in a dedicated "Attachments" section:

  • File List: Each attachment shows:
    • File type icon (image, PDF, document)
    • Original filename
    • File size (formatted, e.g., "14.07 KB")

Comments and Replies

The forum supports threaded comments (replies) with hierarchical structure, allowing nested discussions and replies to specific comments.

Click to view full size

Visual demonstration of hierarchical comments structure

Hierarchy of Comments

Structure: Comments are organized in a tree structure where:

  • Top-level Posts: Direct replies to the topic (no parent)
  • Nested Replies: Replies to other comments (have a parent_post_id)
  • Visual Indentation: Nested replies are visually indented with a curved arrow indicating the reply relationship
  • Depth Levels: Replies can be nested multiple levels deep (reply, reply-2, reply-3 CSS classes)

Visual Indicators:

  • A curved arrow (↪) appears on the left side of nested replies
  • Replies are indented based on their depth level
  • Each level has slightly different styling to show the hierarchy

Implementation: The hierarchy is built by buildPostTree() function in ForumController.php, which organizes posts by parent_post_id. The tree structure is rendered recursively by renderPost(post, depth) in topic.js.

Database: Posts are stored in the doctor_forum_posts table with a parent_post_id column. If parent_post_id is NULL, the post is a top-level reply. Otherwise, it's a reply to the post with that ID.

Posting Replies

Reply Form: A "Post a Reply" form appears at the bottom of the topic page with:

  • Rich Text Editor: Same formatting toolbar as topic creation
  • Content Area: Contenteditable div for typing the reply
  • Image Upload: "Add Images" button for uploading images
  • File Attachments: "Add Files" button for uploading documents
  • Post Reply Button: Submits the reply

Replying to Specific Comments:

  • Click the "Reply" button on any comment
  • The reply form appears with a highlighted section showing the parent comment
  • Type your reply and click "Post Reply"
  • Your reply will appear nested under the parent comment

Implementation: Replies are created via submitReply() function in topic.js, calling POST /api/forum/posts with topic_id, parent_post_id (if replying to a comment), and content.

Like and Dislike on Comments

Functionality: Each comment (reply) has like and dislike buttons:

  • Like Button (👍): Thumbs up icon with like count
  • Dislike Button (👎): Thumbs down icon with dislike count
  • Active State: If you've liked a comment, the like button is highlighted (green). If you've disliked, the dislike button is highlighted (red)
  • Toggle Behavior: Clicking like when already liked removes the like. Clicking dislike when already disliked removes the dislike. Clicking like when disliked switches to like (and vice versa)

Real-time Updates: Like/dislike counts update immediately after clicking, without page refresh.

Implementation: Likes/dislikes are handled by toggleLike(postId, isLike) function in topic.js, calling POST /api/forum/posts/{id}/like or POST /api/forum/posts/{id}/dislike endpoints in ForumController.php.

Database: Likes/dislikes are stored in the doctor_forum_post_likes table with post_id, user_id, and is_like (1 for like, 0 for dislike). Counts are stored in likes_count and dislikes_count columns of doctor_forum_posts table.

Edit Comments

Permissions: Only the comment author or admins can edit comments.

How to Edit:

  • Click the edit icon (pencil) in the top-right corner of your comment
  • The comment content becomes editable
  • Make your changes
  • Click "Save" to save changes or "Cancel" to discard

Implementation: Editing is handled by editPost(postId) function in topic.js, calling PUT /api/forum/posts/{id} endpoint with updated content.

Delete Comments

Permissions: Only the comment author or admins can delete comments.

How to Delete:

  • Click the delete icon (trash) in the top-right corner of your comment
  • A confirmation modal appears
  • Confirm deletion
  • The comment is removed (note: if a comment has replies, those replies may also be deleted or handled based on cascade rules)

Implementation: Deletion is handled by deletePostConfirm(postId) and deletePost(postId) functions in topic.js, calling DELETE /api/forum/posts/{id} endpoint in ForumController.php.

Database: Deleting a post updates the topic's replies_count to decrement by 1. The post and its associated data (images, attachments, likes) are deleted from the database.

Like and Dislike on Topics

Topics can be liked or disliked to express agreement or disagreement with the discussion.

Topic Like/Dislike Functionality

Display: Topic cards show like and dislike counts with icons (👍 for likes, 👎 for dislikes).

Functionality: Similar to comment likes/dislikes:

  • Click like to like the topic (or remove like if already liked)
  • Click dislike to dislike the topic (or remove dislike if already disliked)
  • Switching between like and dislike is supported

Implementation: Topic likes/dislikes are handled by toggleTopicLike(topicId, isLike) function in forum_index.js or topic.js, calling POST /api/forum/topics/{id}/like or POST /api/forum/topics/{id}/dislike endpoints in ForumController.php.

Database: Topic likes/dislikes are stored in the doctor_forum_topic_likes table with topic_id, user_id, and is_like. Counts are stored in likes_count and dislikes_count columns of doctor_forum_topics table.

Edit Function

Topics can be edited by their authors or admins to update content, tags, category, or attachments.

Edit Topic

Permissions: Only the topic author or admins can edit topics.

How to Edit:

  • Open the topic page
  • Click the edit icon (pencil) in the top-right corner
  • An edit modal appears with the same form fields as "Create New Discussion"
  • Modify title, category, content, tags, or attachments
  • Click "Save Changes" to update or "Cancel" to discard

Editable Fields:

  • Title
  • Category
  • Content (rich text)
  • Meta Tags (add/remove tags)
  • Attachments (add/remove files)
  • Pin status (admins only, or all doctors if enabled)

Implementation: Editing is handled by editTopic(topicId) function in topic.js, which loads the topic data and opens an edit modal. Changes are saved via PUT /api/forum/topics/{id} endpoint in ForumController.php.

Delete Function

Topics can be deleted by their authors or admins. Deletion is permanent and removes the topic and all associated data.

Delete Topic

Permissions: Only the topic author or admins can delete topics.

How to Delete:

  • Open the topic page
  • Click the delete icon (trash) in the top-right corner
  • A confirmation modal appears warning that deletion is permanent
  • Confirm deletion
  • The topic and all its replies, attachments, and associated data are deleted
  • You are redirected back to the forum main page

Warning: Deletion is permanent and cannot be undone. All replies, attachments, images, and likes associated with the topic will also be deleted.

Implementation: Deletion is handled by deleteTopicConfirm(topicId) and deleteTopic(topicId) functions in topic.js, calling DELETE /api/forum/topics/{id} endpoint in ForumController.php.

Database: Deleting a topic removes it from the doctor_forum_topics table. Associated data (posts, tags, attachments, likes) may be deleted via cascade rules or explicit deletion queries.

Technical Implementation

Technical details about the Discussion Forum implementation, including key files, API endpoints, database structure, and JavaScript functions.

Key Files

  • Controller: @app/Controllers/ForumController.php - Handles all forum-related API endpoints and business logic
  • Main Page View: @app/Views/doctor/forum/index.php - Renders the main forum page with category stats, tags, search, and topic list
  • Topic Page View: @app/Views/doctor/forum/topic.php - Renders individual topic pages with replies
  • Main Page JavaScript: @app/Views/doctor/assets/js/forum_index.js - Handles forum main page interactions, topic loading, filtering, search, and topic creation
  • Topic Page JavaScript: @app/Views/doctor/assets/js/topic.js - Handles topic page interactions, reply posting, like/dislike, edit/delete, and comment hierarchy rendering

API Endpoints
